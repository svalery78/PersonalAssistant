# Персональный помощник ВКонтакте с OpenRouter

FastAPI принимает сообщения VK Callback API, отправляет историю и системные
инструкции в OpenRouter Chat Completions API и возвращает ответ через VK API.

## Запуск

Требуется Python 3.10 или новее. Выполните в папке PersonalAssistant:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env_example .env
```

Заполните `.env`: `OPENROUTER_API_KEY` — ключ OpenRouter,
`OPENROUTER_MODEL` — полный идентификатор выбранной модели из
[каталога](https://openrouter.ai/models), а также три токена ВКонтакте.
Ключ OpenAI и Prompt ID больше не нужны. Настройте инструкции в
`system_prompt.txt`: исходный текст из Playground нужно перенести туда вручную.
Пути к промпту и базе разрешаются относительно папки проекта.

```bash
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Для другого адреса или порта измените аргументы команды (APP_HOST и APP_PORT
доступны в config.py для программного запуска).
Откройте публичный HTTPS-адрес через ngrok и укажите в настройках Callback API
сообщества `https://ваш-домен/vk/callback`. Настройте secret, подтверждение
сервера и событие `message_new`. Отправьте сообщение сообществу.

## Контекст и отличия от исходного примера

- `openrouter_client.py` вызывает `/api/v1/chat/completions` через requests.
- `db.py` хранит текст последних `HISTORY_MAX_TURNS` пар вопрос–ответ каждого
  пользователя в SQLite. При каждом запросе история передаётся модели заново.
  Ограничение по числу пар не гарантирует попадания в токенный лимит модели;
  при длинных сообщениях уменьшите HISTORY_MAX_TURNS или выполните `/reset`.
- `/reset` удаляет локальную историю пользователя. Она сохраняется при
  перезапуске сервера, пока доступен `bot.db`.
- Старая таблица `user_conversations`, если она есть, остаётся нетронутой и
  не используется. Старые conversation_id нельзя использовать как историю
  Chat Completions; переписка начинается заново.
- Prompt ID и OpenAI File Search не передаются в этот API. Поиск по загруженным
  в Playground материалам в этой версии отсутствует. Для него потребуется
  отдельный поиск по документам (RAG) и передача найденных фрагментов модели.
- Как и в исходном примере, ключ истории — from_id. Для групповых бесед
  следует отдельно определить изоляцию контекста по peer_id.

Это учебный сервер: повторная доставка событий VK не дедуплицируется,
одновременные сообщения пользователя не сериализуются, а обработка ответа
происходит до возврата `ok`. Для рабочего бота нужна очередь с быстрым
подтверждением Callback API.

Документация API: https://openrouter.ai/docs/quickstart
